# 哭泣动作开发计划（v1.2）

> 目标：新增第四个 Q 键动作「哭泣」——整身大哭姿势（`><` 闭眼 + 泪珠 + 张嘴哭喊 + 双手攥拳抵胸），
> 并顺手把「单帧姿势类动作」的接入方式通用化，让后续动作（打招呼、睡觉、被戳……）的开发成本降到
> 「一张参考图 + 一份管线配置 + 一条注册」。

## 一、现状盘点（2026-09-17）

### 架构

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 主进程 | `main.js` | 透明置顶窗口、鼠标穿透、托盘、位置记忆、全局 Q 热键转发（`pet:hotkey` → 渲染进程） |
| 渲染进程 | `src/renderer.js` | Canvas 2D 纸偶合成 + 动作状态机 + Q 键循环 + 预览截图 |

| Live2D | `src/live2d*.js`、`assets/live2d/haru` | 独立渲染路径，占位验证中，**本计划不涉及** |

### 已有动作与机制

| 动作 | 实现方式 | 计时槽 | 播放形态 |
| --- | --- | --- | --- |
| 踢腿（单击/Q） | 程序化纸偶动画 | `A.click.t` | 小跳 + 交替踢腿，1.05s |
| 害羞（Q/待机随机 16%） | **单帧整身图** `shy_00.webp` | `A.shy.t` | 预备吸气(纸偶) → 整身图淡入 → 保持 → 淡出，叠加呼吸/后仰轻摇 |
| 开心（Q） | **73 帧视频序列** `happy_*.webp` @12fps | `A.clip.t` | 整段播放，前后淡入淡出 |

## 二、技术路线

哭泣与害羞素材形态完全一致（整身参考图、白底、同规格生成图）→ **复用害羞的「单帧姿势 clip」管线**，
不新造渲染机制。视频帧序列路线留给需要肢体大位移的动作（挥手、跳舞）。

同时做一次**轻量框架化**（见阶段 2），消除「每加一个动作就复制一份 shy 逻辑」的问题。

## 三、分阶段实施

### 阶段 0 · 分支准备（10 分钟）

- `git checkout -b feat/cry-action`（合入前自测通过再并回 main）

### 阶段 1 · 素材管线：`tools/cry_pose_pack.py`（0.5～1 天）

从 `shy_pose_pack.py` 派生，流程六步不变，差异点如下：

| 步骤 | 害羞脚本做法 | 哭泣需要做的 |
| --- | --- | --- |
| 1. 去底 | 泛洪 `near_white>=238`，边界起刷 | 相同。**先跑一次看水印 bbox**，调整 `shy_arr[2140:, 1400:, :] = 255` 的清 watermark 区域（两张图水印位置可能不同） |
| 2. 刘海 NCC 对齐 | 模板区 `TX 500..1200, TY 580..800` 搜 base 刘海区 | 大概率可直接复用（同规格生成图）；跑完看打印的 ncc 值与 dbg 图，若拉偏则挪模板区 |
| 3. 眉眼暗结构精化 | 闭眼线/眉毛 `lum<105` 重叠率微调平移 | **哭泣是闭眼哭脸，暗结构分布不同，此步可能拉偏** → 对齐已好就跳过；或把匹配区改为双眼整体 |
| 4. 包围盒 + 锚点配准 | 高 622 / 脚线 640 / 居中 266.5 | 相同（基准统一，勿改） |
| 5. 肤色调和 + 去白边 | 额头带 `COLOR_PAIR_BAND` 中位数配对 + 半透明像素反混合 | 相同。注意：泪珠高光、牙齿是**内部白色**，泛洪从边界起不会误删；若泪珠贴着轮廓边缘导致缺口，局部收紧阈值再补 |
| 6. 输出 | `shy_00.webp` + manifest `clips.shy` | 输出 `cry_00.webp` + manifest `clips.cry = {count:1, fps:1, ext:'webp', ox, oy, w, h:622}`；dbg 合成图存 `tools/dbg_cry_pose.png` |

**验收**：`tools/dbg_cry_pose.png` 中脚底贴线、身高/居中与纸偶一致；与 `base.png` 并排无肉眼色调差；
马尾、靴子边缘 400% 放大无白边。

> 管线代码建议抽公共库：`flood_alpha / masked_ncc / 配准 / defringe` 提为 `tools/pose_pack_lib.py`，
> 害羞与哭泣脚本都变成「源图路径 + 水印区 + 输出名」的薄配置。这一步可现在做，也可以等第三个整身动作出现时再做（见「七」）。

### 阶段 2 · 渲染接入 + 轻量框架化（0.5 天）

改动集中在 `src/renderer.js` 三处：

1. **动作注册表替代 if-else 链**

   ```js
   // 现状 L106-111: hotkeyNext 0/1/2 的 if-else
   // 改为:
   const ACTIONS = ['kick', 'shy', 'happy', 'cry'];
   function playNextAction() { startAction(ACTIONS[hotkeyNext % ACTIONS.length]); hotkeyNext++; }
   ```

   `startAction(name)` 分发到 `startKick/startShy/startHappy/startCry`（后续新动作 = 数组加一项 + 一个 start 函数）。

2. **「单帧姿势 clip」泛化**（核心）

   - `A.shy = {t}` 槽位改为通用 `A.pose = {name:'shy'|'cry', t}`，或并列加 `A.cry` 槽（取前者，避免第三份重复）
   - `SHY` 曲线常量改为按动作查表：

     ```js
     const POSE = {
       shy: { wind: 0.2,  raise: 0.34, hold: 2.3, fall: 0.5, sob: null },
       cry: { wind: 0.25, raise: 0.45, hold: 3.2, fall: 0.8, sob: { hz: 1.1, dy: 1.8, lean: 0.5 } },
     };
     ```

   - `render()` L341 的 `if (pose.clip.name === 'shy')` 改为「pose 型 clip 一律套脚底锚点变换」
     （可用 manifest `clips[name].count === 1` 或显式 `type:'pose'` 标记判断）
   - **哭泣的动效**：淡入后保持期内叠加「啜泣节奏」——以 `sob.hz ≈ 1.1Hz` 周期性轻微下沉/耸肩
     （作用在 hop 上，幅度 ~2px）+ 微幅 lean 抖动，比害羞的 0.35Hz 慢摇更快更碎，呈现一抽一抽的哭感。
     尾巴垂落不动（`wag` 置 0），耳朵微垂（ earL/earR 加 -1.5° 偏置）——仅纸偶阶段的预备帧有效，
     整身图阶段靠整图变换。

3. **runPreview() 加哭泣段**：`clip:{name:'cry', i:0, alpha:1}` → `capture('cry')`，GIF 段截取 hold 前 ~2s。

**验收**：`npm start` 后 Q 循环 = 踢腿 → 害羞 → 开心 → 哭泣 → 循环；哭泣播放中拖拽可打断且恢复正常；
害羞/开心行为与改动前完全一致（回归）。

### 阶段 3 · 效果打磨（0.5 天，按评审意见迭代）

- 啜泣频率/幅度、hold 时长（大哭 3~4s 比害羞 2.3s 长）、淡出速度调参
- **可选增强：泪滴粒子**——在整身图之上按 manifest 声明的两个眼角坐标，程序化画小水滴周期性下落
  （Canvas 画椭圆 + 高光，`clip` 期间叠加）。v1.2 可不做，列为 v1.3 候选
- **待机随机触发：不建议加入**。害羞适合日常随机，大哭情绪强度高，随机哭会突兀；
  保持仅 Q 键（若以后要做情绪系统再开放，如「连续拖拽甩她 → 哭」）

### 阶段 4 · 验证与发布（0.5 天）

1. `npm run preview` 生成 `preview/cry.png` 与 GIF 帧；`python tools/make_gif.py` 重出 `docs/demo.gif`（含哭泣段）
2. README 更新：动作数（三 → 四）、Q 键循环说明、素材管线表加一行「哭泣整身姿势」、演示动图
3. 版本号 v1.1 → v1.2：`package.json` `version` 与 `build.portable.artifactName` 中的 v1.1 字样
4. 冒烟：`PET_SMOKE=1 npm start`（6s 自动退出无报错）；正常模式手测缩放/置顶/穿透/位置记忆
5. `npm run dist` 出 `Gilberta.Desktop.v1.2.Windows.x64.exe`，合分支、打 tag、发 Release

## 四、风险与对策

| 风险 | 概率 | 对策 |
| --- | --- | --- |
| 刘海 NCC 对齐拉偏（闭眼哭脸 vs 害羞脸结构差异） | 中 | 看 ncc 打印值与 dbg 图；拉偏则挪模板区、跳过暗结构精化步（NCC 单独通常已够） |
| 水印区域与害羞图不同，残渣混入最大连通域 | 中 | 阶段 1 第一步先单独跑去底 + 包围盒可视化，按实际 bbox 改清水印坐标 |
| 泪珠/牙齿白色被判成背景 | 低 | 泛洪从画布边界起，内部白色不连通不受影响；仅当白色贴住轮廓才有风险，收紧阈值或局部修补 |
| 张嘴哭喊的口腔大暗区影响肤色调准 | 低 | 调准带在额头（`COLOR_PAIR_BAND`），不涉及口腔；保持不动 |
| webp 有损压缩让泪珠高光发闷 | 低 | quality=93 与现有一致；不行升 95 或该帧局部用 png |
| 重构动作注册表时回归破坏害羞/开心 | 低 | 改动小且集中；逐动作手测 + preview GIF 对照 |
